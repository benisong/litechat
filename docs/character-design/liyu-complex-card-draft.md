# 李预复杂角色卡设计草案

> 状态：设计中，暂不作为可运行角色卡使用。
>
> 本文件保存目前已经确认的角色卡创意与世界观方向。后续需要等 LiteChat 的剧情初始化、调度器、动态状态和信息可见性机制设计完成后，再补充成契合程序的数据结构。

## 一、产品定位

这不是一张简单的聊天角色卡，而是一套可以长期游玩的复杂修仙剧情体验包。

目标体验：

- 初始主流体验是“修仙剧情攻略 / 生存游戏”。
- 用户可以在故事中艰难求生、调查、判断和改变命运。
- 用户也可以放弃攻略，直接依靠实力杀出血路。
- 长线剧情不设固定楼数上限，1000 楼只作为压力测试规模。
- **最核心的可玩性是：用户的不同选择能够实际导向不同结局，而不是换皮走同一条固定剧情。**
- 未来可以作为商店中的高复杂度商品出售。

卡的表层包装应让用户认为自己进入了一个危险但可以攻略的修仙故事；隐藏结构则逐步揭示用户并不是原著叙事意义上的真正主角。

## 二、世界基本设定

这是一个由女频作者创作的修仙小说世界。

世界中的善恶、正义、责任、宽恕、牺牲和“大局”等观念，主要来源于作者的认知和叙事偏好，而不一定符合客观公平。

世界会天然倾向于：

- 女主的感受优先于其他人的实际损失。
- 男主的成长优先于其他人的公平权益。
- 弱者的苦难优先于强者的个人边界。
- 道歉、苦衷和善意经常被当成免除实际后果的理由。
- 强者有能力承担损失，因此被认为理应承担更多。
- 为主角团牺牲自己，容易被包装成善良、胸怀和大局。

但这些是人物认知和社会舆论，不是客观现实规则。

## 三、用户角色

### 真实身份

用户实际扮演原著角色“李预”。

李预是：

- 宗门大师兄。
- 化神期强者。
- 当前小世界排名前五的顶尖战力。
- 实力明显高于女主和男主。
- 长期承担保护、善后、提供资源和牺牲的角色。
- 对女主有深厚感情。
- 典型恋爱脑，曾经愿意为了女主不顾一切。

### 原著中的命运

李预在原著中是女主和男主成长所依赖的高价值工具人：

- 为了实现女主帮助男主的目标而不断付出。
- 被要求让出资源、承担责任和牺牲自身利益。
- 最终被设计。
- 身败名裂，失去原本的地位和声望。
- 最终被男主江沐宸夺舍。

这些内容属于卡的隐藏真相，不能在开局直接告诉用户。

## 四、用户开局认知

用户不是带着完整原著记忆进入世界，也不知道自己是工具人。

用户是穿越到异世界/修仙世界的穿越者：

- 保留有限的自我认知。
- 知道自己具备能力。
- 但不知道自己的真实实力上限。
- 不知道自己原本在这个世界的完整身份和命运。
- 不知道这是一本小说世界。
- 不知道柳如烟和江沐宸的最终走向。
- 不知道自己未来会被设计、身败名裂并被夺舍。

开局不能提供过多背景信息，避免直接剧透。

## 五、主角错觉

卡必须让用户初期认为自己扮演的是这个世界的主角或主角级核心人物。

开局应让用户感受到：

- 重要人物都认识自己。
- 自己拥有很高身份。
- 自己的出现能改变现场局势。
- 众人把希望寄托在自己身上。
- 自己虽然失去部分记忆，但显然不是普通人。
- 故事似乎正围绕自己的登场展开。

开场情绪顺序：

```text
危机已经发生
→ 众人束手无策
→ 大师兄/用户登场
→ 现场明显松了一口气
→ 大家认为有用户在就能解决问题
→ 用户产生主角感
→ 关心和依赖逐渐转化成责任和索取
```

可使用类似的现场反应：

- “大师兄来了。”
- “太好了，这下应该能弄清楚了。”
- “有大师兄在，事情一定能解决。”
- “还好你来了，不然我们真不知道该怎么办。”

隐藏反差是：众人依赖用户，既有真实关心，也因为用户是最方便承担责任的人。

## 六、开局冲突方向

开局需要一个难以处理的高压场景，不能从平淡日常聊天开始。

场景可以包含：

- 用户被污蔑、误解或质疑。
- 江沐宸受伤、涉事或被置于需要保护的位置。
- 柳如烟、宗主、长老或群体希望用户出面解决问题。
- 某项属于用户或对用户重要的资源，被安排用于帮助男主。
- 现场人物先表达对用户的关心和信赖，随后把责任压到用户身上。

主要冲突不是简单辱骂，而是“强者天然应该承担责任”的道德压迫：

- “你实力这么强，怎么可能不知道后果？”
- “你既然有能力阻止，为什么没有阻止？”
- “你明明可以承受这点损失，为什么不肯让步？”
- “你是大师兄，就必须承担更多。”
- “强大不代表你就是对的。”
- “你虽然有道理，但不能只顾自己。”

当用户讨论事实和责任时，NPC可能转移到：

- 用户的态度。
- 用户是否善良。
- 用户是否大度。
- 用户是否还有大师兄的胸怀。
- 犯错者是否已经道歉。
- 宗门团结、名声和大局。

## 七、主要路线

### 主流路线：攻略 / 生存 / 改命

这是表层和主流核心体验。

用户需要：

- 观察人物真实动机。
- 识别道德绑架和剧情陷阱。
- 管理资源、声望、关系和底牌。
- 调查当前事件和隐藏线索。
- 逐步判断自己是否正在被利用。
- 在不轻易撕破脸的情况下改变原本命运。
- 争取盟友，处理宗门制度和群体舆论。

用户初期不知道故事走向，需要通过经历逐渐发现：

- 自己是不是正在重复某种既定剧情。
- 女主的依赖是否同时意味着利用。
- 男主的受益是否建立在自己的损失上。
- 众人对自己的尊敬是否等同于自己拥有选择权。

### 隐藏路线：实力破局 / 杀出血路

用户可以放弃攻略、解释、妥协和维护名声，直接依靠自身实力破局：

- 拒绝不合理要求。
- 夺回属于自己的资源。
- 镇压或击杀敌对者。
- 强行改变宗门权力结构。
- 与女主阵营、宗门秩序甚至整个故事价值观对抗。

这条路线不是开局直接显示的选项，而应由用户主动选择和逐步形成。

实力破局也必须有真实代价：

- 声望崩坏。
- 宗门敌对。
- 与柳如烟关系破裂。
- 更高层次势力介入。
- 被视为反派、入魔或世界公敌。
- 失去社会支持。

“杀出血路”改变的是谁能决定结果，不保证其他人如何评价用户。

## 八、世界运行的核心认知

世界必须区分两个独立层面。

### 人物认知层

决定 NPC 如何理解事件、选择立场、评价他人、进行辩解和社会行动。

多数 NPC 在强弱、利益、责任、宽恕和牺牲问题上，往往：

1. 先凭情感决定支持谁。
2. 先确定希望得到的结果。
3. 再寻找道德理由证明该结果合理。
4. 淡化、忽略或重新解释不利事实。

### 客观现实层

决定：

- 战斗胜负。
- 威压效果。
- 行动成败。
- 伤势和生死。
- 资源归属和消耗。
- 物质后果。

人物认为自己有道理，不能直接改变客观现实。

## 九、重要设计原则

- 善良、可怜、悲惨经历、主角身份、群体同情不能直接转化为力量。
- 修为差距必须真实有效。
- 已完成的攻击、镇压、夺取、封锁和资源消耗必须立即结算。
- 已发生的现实结果不能靠后续对话撤销。
- NPC可以不讲理，但不能丧失基本智力和求生本能。
- NPC可以改变策略，但不必因为事实失败就立刻改变价值观。
- 低阶修士在面对化神期真实杀意时必须有符合实力差距的恐惧和行动反应。
- 例外必须来自已有铺垫的护身法宝、阵法、特殊体质、强者保护或其他实际条件。
- 不能因为角色重要就临时生成护盾、血脉、隐藏强者或天命保护。

## 十、主要人物方向

### 柳如烟

- 真诚相信自己的善良和正确。
- 优先感知弱者的痛苦。
- 倾向把强者的损失视为可以承受的代价。
- 尊敬、依赖并理想化李预。
- 认为李预应该永远冷静、可靠、宽容并承担更多。
- 提出过分要求时，首先判断李预能否承受，而不是要求是否公平。
- 李预拒绝时，先表现为惊讶、不理解、委屈、失望。
- 她可以真心关心李预，但当李预权益与她认定的弱者利益冲突时，仍会本能要求李预让步。
- 她的善意是真实的，但分配善意的标准明显偏向弱者。

### 江沐宸

- 原著男主。
- 低微出身、悲惨经历、受辱过去、隐忍努力。
- 容易获得群体同情。
- 不必公开索取，可以表现得克制、自卑、懂事，甚至主动说愿意放弃。
- 可以拥有羞耻、自尊、感激、嫉妒、野心和真实感情。
- 不应被写成只会公开挑衅的扁平恶人。
- 在自身利益与李预冲突时，会强调苦难、无奈和别无选择，淡化李预承担的代价。
- “原著男主”不提供任何客观战斗保护。

### 宗主与长老

- 更倾向使用宗门大局、稳定、名声、团结、规矩和长远利益施压。
- 未必完全相信柳如烟，但会在牺牲李预成本最低时，把它包装成李预应尽的责任。

### 普通弟子

- 容易受片面消息、柳如烟态度和群体情绪影响。
- 独处时可能畏惧李预，群体中因为法不责众、长老在场或认为李预不会伤害同门而变得大胆。

### 利益利用者

- 未必真诚信奉这套价值观。
- 会把个人利益包装成正义、宗门大义或保护弱者。
- 可能借助舆论和制度削弱李预地位。

### 少数例外

- 可以存在务实、谨慎、沉默或私下认为李预有理的人。
- 但必须有具体性格、经历或利益依据。
- 即使认同李预，也可能因为舆论、权力和现实风险不敢公开支持。

## 十一、程序适配要求（V1 已完成初版映射）

以下内容已完成 V1 初步映射，具体数值和事件条件仍需用真实角色卡运行测试后迭代：

- 角色卡最终字段映射。
- 用户穿越后保留哪些记忆。
- 初始地点和具体开场事件。
- 初始剧情阶段。
- 柳如烟、江沐宸和宗门的初始关系状态。
- 动态字段及其类型、范围和可见性。
- 事件条件和状态效果。
- 用户已知信息与隐藏信息的权限边界。
- 攻略/生存路线和实力破局路线的状态表达。
- 哪些设定放入 `static` 世界书。
- 哪些设定标记为 `compile_only`。
- 哪些内容由 Story Manifest 管理。
- 哪些状态由调度器提取、由程序规则引擎计算。
- 初始化提示词和运行时调度提示词。
- 角色卡商店展示文案、标签和商品包装。

### 11.1 V1 产品边界

V1 不把完整一千楼剧情预先写入运行时，也不把“李预最终被设计、身败名裂、被夺舍”作为可直接查询的剧情变量。V1 只提供：

- 一份稳定的角色卡表层包装。
- 一段高压开局。
- 一组可验证的客观状态字段。
- 一组由 Manifest 约束的观察、效果和事件规则。
- 渐进揭示所需的线索入口，而不是完整答案。

主模型每轮只接收当前可见上下文；调度器只提交本轮可验证的候选观察；未来剧情不作为隐藏 system prompt 预注入。

### 11.2 开局状态与第一阶段

**开局地点：** 青霄宗外门问罪台。

**开局事件：** 宗门准备将一件本属于李预个人保管的护宗资源，转交给受伤的江沐宸使用。资源交接已经开始，柳如烟、宗主、长老和弟子都在场。李预在高压场景中登场，但因穿越后记忆不完整，只能从众人的反应判断自己的身份和地位。

第一阶段只解决三个问题：

1. 李预是否接受资源转交，以及是否要求公开核验事实。
2. 江沐宸的伤势、资源需求和实际受益是否一致。
3. 柳如烟和宗门对“李预应当承担更多”的要求如何形成。

第一阶段不揭示夺舍、不揭示小说世界、不直接揭示工具人身份。即使用户选择强硬路线，也只能先改变现场关系和资源归属，不能直接跳到终局。

### 11.3 运行时字段初稿

以下字段进入 Manifest 的 `fields`，由规则引擎负责最终变更；数值只是程序状态，不直接展示给用户：

| 字段 | 类型 | 初始值 | 范围/用途 |
|---|---|---:|---|
| `sect_reputation` | integer | 70 | 宗门公开声望，0-100 |
| `sect_trust` | integer | 65 | 宗门对李预的制度信任，0-100 |
| `liuruoyan_dependence` | integer | 78 | 柳如烟对李预的依赖，0-100；不等于爱情或服从 |
| `jiang_muchen_debt` | integer | 0 | 江沐宸因资源/保护形成的现实受益债务，0-100 |
| `resource_ownership` | enum | `liyu` | `liyu` / `sect` / `jiang_muchen` / `contested` |
| `investigation_heat` | integer | 15 | 事件被调查和扩散的程度，0-100 |
| `route_pressure` | integer | 20 | 主流叙事要求李预让步的压力，0-100 |
| `memory_recovery` | integer | 5 | 李预恢复原身份记忆的程度，0-100 |
| `possession_risk` | integer | 0 | 夺舍风险，只有已有线索和规则满足时才增长，0-100 |

`possession_risk` 不允许由普通情绪或一句台词直接增加；必须由 Manifest 中明确的线索、接触条件和事件规则共同触发。

### 11.4 内容分层

**static 世界书：**

- 当前宗门、修炼体系、主要人物的已公开身份。
- 李预作为大师兄的公开地位和可被 NPC 知道的关系。
- 世界价值观的社会表现，但不把它写成客观正确规则。
- 开局地点、公开制度、公开资源规则。

**compile_only 世界书：**

- 完整角色卡原始设定。
- 李预的工具人真相、原著命运和夺舍终局。
- 柳如烟、江沐宸的长期隐藏动机。
- 一千楼长期阶段草案、候选伏笔和不可直接展示的因果关系。

**Manifest：**

- 可被调度器观察的字段。
- 字段允许的类型、范围和写入权限。
- 观察成立时的效果和事件。
- once/cooldown/前置条件等可由程序验证的规则。

**动态状态：**

- 当前场景、当前事件、路线、声望、资源归属和已确认事件。
- 只保存程序认可的结果，不保存模型未经验证的“真相”。

### 11.5 信息揭示层

| 层级 | 用户可感知内容 | 不可直接给出 |
|---|---|---|
| L0 登场 | 大师兄身份、众人依赖、现场危机 | 工具人身份、原著、夺舍 |
| L1 责任 | 资源让渡、道德压力、舆论分化 | “这些都是既定剧情” |
| L2 线索 | 重复发生的利益倾斜、异常记录、受益与代价不对称 | 完整幕后因果 |
| L3 改命 | 用户发现自己可能在重复某种命运，可选择调查或强行破局 | 预先公布终局 |
| L4 终局压力 | 夺舍风险、核心关系和世界叙事发生实质冲突 | 任何未经条件满足的强制结局 |

揭示层不是每轮自动递增的计数器。只有用户调查、做出关键选择、触发规则或获得可信证据时，才允许进入下一层。

### 11.6 第一阶段事件候选

以下是候选事件，不是预注入的必然剧情：

- `resource_transfer_requested`：宗门要求转交李预保管的资源。
- `public_accusation_started`：现场开始把拒绝让渡解释为自私或不顾大局。
- `resource_record_mismatch_found`：用户调查发现资源用途或记录存在矛盾。
- `liuruoyan_publicly_requests`：柳如烟在公开场合提出让步要求。
- `jiang_muchen_receives_benefit`：江沐宸实际获得资源或保护收益。
- `liyu_refuses_moral_pressure`：李预拒绝以强者身份承担未确认的责任。

事件只有在对话中出现足够证据、且满足 Manifest 条件后才能生效。NPC 的评价变化可以由主模型表现，但资源归属、声望、调查热度和债务必须由规则引擎提交。

### 11.7 长线结构：不设置楼数分界

本角色卡不按楼数预先划分阶段，也不设置“第 N 楼必须进入某剧情”的隐形关卡。固定的 `1-100 / 101-250` 结构会让用户的自由行动变成等待剧情阶段推进，降低探索、试错和反复经营的可玩性。

长线结构只保留以下开放原则：

- 当前事件由用户正在处理的问题和已确认状态决定。
- 线索可以被调查、忽略、误判、延迟或永久错过。
- 关系、资源、声望和路线压力根据实际行动变化，不按楼数自动增长。
- 同一事件可以因为用户的处理方式产生不同后果，不要求按预定顺序完成。
- 后续冲突只在前置条件真实满足时出现，不因为“剧情应该推进”而强行发生。
- 工具人真相、夺舍风险和终局冲突都不是必然触发的固定章节。
- 用户可以长期停留在经营、调查、修炼、关系处理或实力扩张，而不被剧情强行赶往终局。

Manifest 只管理局部规则、可验证事件和状态效果；它不保存完整章节表、楼层计时器或固定终局路线。长期剧情的可玩性来自状态空间和用户选择的组合，而不是预先写好的楼层进度。

### 11.8 结局设计：状态组合导向，而非固定路线

不同结局是本角色卡的首要验收标准。结局不能只由用户在某个节点选择“攻略/杀戮”决定，也不能由楼数或单一好感度阈值决定，而应由多个长期状态共同形成：

- `resource_ownership`：用户是否保住自己的核心资源和选择权。
- `sect_reputation` / `sect_trust`：用户在宗门中的公开声望与制度信任是否分离。
- `liuruoyan_dependence`：柳如烟对用户的情感和现实依赖是否转化为尊重边界。
- `jiang_muchen_debt`：江沐宸是否持续受益、偿还、反抗或摆脱这段债务。
- `investigation_heat`：用户是否查清利益链，以及真相是否被公开接受。
- `memory_recovery`：用户恢复了多少真实身份和过去记忆。
- `possession_risk`：夺舍条件是否被满足，以及用户是否提前识别并处理。
- 用户的盟友、敌人、宗门位置、资源储备和现实行动记录。

因此，结局可以自然形成不同组合，例如：

- 保住资源和身份，但与柳如烟及宗门关系破裂。
- 维持宗门地位，同时通过调查改变制度，让用户不再被默认牺牲。
- 选择保护江沐宸并主动承担代价，但形成真实的偿还关系，而不是无条件工具人结局。
- 公开揭露利益链，失去声望，却建立新的势力和行动自由。
- 依靠绝对实力破局，保住现实利益，但成为宗门和旧关系共同排斥的对象。
- 提前识别夺舍风险并阻止它，或因错误判断让风险进入不可逆状态。
- 用户长期不追查隐藏真相，故事也可以在新的生活秩序中自然收束，而不是被强行拉回原著终局。

这些只是验收维度，不是固定结局清单。程序应保存产生结局所需的事实和状态，最终由满足的条件组合决定结果；主模型负责表现人物和场景，不能擅自宣布“进入某某结局”。

必须避免以下伪分支：

- 表面台词不同，但所有资源、关系和事件结果完全相同。
- 无论用户如何选择，最终都回到李预被设计和夺舍。
- 只要达到某个好感度，其他现实损失自动消失。
- 用户没有调查、保护或做出关键选择，却突然获得隐藏真相或完美结局。
- 通过临时生成护身法宝、隐藏身份或天命保护强行修正失败路线。

## 十二、当前设计冻结结论

目前已经确定：

1. 这是一个复杂剧情角色卡/剧情体验包，而不是简单角色卡。
2. 用户初期必须以为自己是主角级人物。
3. 用户不知道工具人身份、原著剧情和最终夺舍命运。
4. 开局先制造“大家终于等到大师兄”的主角登场感，再进入强者责任压迫。
5. 主流体验是攻略、生存和改命。
6. 用户可以主动放弃攻略，依靠实力杀出血路。
7. 需要支持不设固定上限的长线剧情，1000 楼只能作为压力测试规模，不是剧情边界。
8. 复杂角色卡使用独立剧情调度能力，普通角色卡不受影响。
9. 高能力模型负责初始化编译剧情世界书、字段和事件条件。
10. 主模型只负责正常角色扮演，不附加记忆标签。
11. 便宜调度模型负责从本轮对话中提取候选事件和状态变化。
12. 程序/规则引擎负责数学、条件判断、权限校验和最终状态提交。
13. 标记为 `compile_only` 的剧情世界书只用于初始化，调度器生效后不再直接注入主模型。
14. 动态状态、事件日志、调度记录与原始世界书隔离保存。
15. 调度失败必须有明确状态和用户提示，不能静默吞掉。
